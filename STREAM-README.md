# UNFUG Community Bot – Twitch Stream Integration

This is the complete existing v11 community bot from source blob a0a5be5ca8cf1245e7a9c5503f0ca02d8d36cbdd, plus the integrated Twitch module. The 96 original slash commands and their implementation are preserved. The two new commands make 98 total. No Discord application or bot token is created. Do not run the old standalone StreamBot alongside this version.

## Features

`/stream setup`, `connect`, `status`, `test`, `live`, `enable`, `disable`: editable Discord announcement, optional role ping, true Twitch live detection, one announcement per stream session, private OAuth authorization. `/streamgiveaway start`, `status`, `end`, `reroll`, `cancel`, `overlay`: Twitch chat participation with `!join` (customizable keyword), unique Twitch user IDs, persisted entries, 1–20 winners, secure random selection, previous-winner exclusion, automatic expiry, and a transparent live OBS overlay. Existing Discord giveaways remain separate.

## First installation

1. Back up your existing repository and Railway data. Create a new GitHub branch named `stream-integration` from main. Upload the contents of this folder into that branch, replacing the original index.js and package.json. Do not upload this folder as one ZIP file. Existing unrelated files and secrets should remain unchanged. Do not upload `.env`, data.json, databases, or tokens. If you have made changes after the referenced v11 commit, use the patch installer on your current source instead of replacing it with this older snapshot.
2. In Railway, keep the existing Bot service, existing DISCORD_TOKEN, existing /data volume and public domain. Do not create another service or another Discord application. Use Node.js 22 (the included .nvmrc and package.json specify this). The original start command remains `node index.js`. The only new runtime dependency is Node's built-in SQLite module; existing discord.js 14.27.0 is retained. Use `npm install` if needed. Do not delete the existing Railway volume.
3. Create an application at https://dev.twitch.tv/console/apps with OAuth Redirect URL `https://bot-production-d58c.up.railway.app/stream/oauth/callback` (use your actual PUBLIC_URL if different). The URL must match exactly, including HTTPS and path. Create a client secret and set the Railway variables below. Never put secrets in GitHub or this chat.
4. Configure the existing Railway service with TWITCH_CHANNEL, TWITCH_CLIENT_ID, TWITCH_CLIENT_SECRET, STREAM_GUILD_ID, and PUBLIC_URL. Keep all existing environment variables untouched. Set STREAM_GUILD_ID to your Community Discord server ID, not a channel ID. PUBLIC_URL must be the existing Railway HTTPS origin without a trailing slash or path. Existing RAILWAY_VOLUME_MOUNT_PATH=/data is used automatically.
5. Deploy the isolated branch to a temporary Railway service/environment for testing if available. A second instance must never log in using the same production DISCORD_TOKEN while the production bot is running. Use a separate test Discord application/token for simultaneous staging, or deploy only after local testing with the production instance stopped. Merge to main only after checks pass. Railway's existing GitHub deployment will then update the original service.
6. In Discord run `/stream connect`. Open the private authorization link and sign in as the actual Twitch broadcaster. Grant `user:read:chat` and `user:write:chat`. The callback saves the access and refresh tokens to the existing private /data volume. Tokens are refreshed automatically. Never paste the token or OAuth callback URL into chat. If authorization fails, check the Railway logs, registered redirect URL, and account.
7. Run `/stream setup` with your announcement channel, optional role and desired text. Available replacements: `{title}`, `{game}`, `{url}`. Run `/stream test` to send a clearly labeled test without any role ping. `/stream status` and `/stream live` check configuration and live state. Automatic checks run approximately every 60 seconds.
8. Run `/streamgiveaway overlay` and copy the private URL into the provided OBS connection script. The overlay is read-only, has no audio, and remains transparent when no giveaway exists. Do not publish the URL. In Discord use `/streamgiveaway start preis:Test dauer:5m gewinner:1`, then type `!join` from a different Twitch account in your stream chat. Confirm the participant count, end the giveaway, and test reroll before giving away a real prize.

## Security and limitations

Stream management is restricted server-side to the configured guild's owner, configured MASTER_USER_IDS, or members with Manage Server permission. The commands also default to Manage Server visibility. The OAuth link is private, single-use and expires after ten minutes. The callback validates the broadcaster account. Tokens and giveaway data are stored in a separate SQLite database in /data; existing data.json is never migrated or overwritten. The overlay exposes only public giveaway state and contains no OAuth credentials. The token database and overlay URL must remain private. The overlay is a capability URL, not a login system.

A single running instance is required for automatic drawing and the Twitch WebSocket session. WebSocket reconnects and token refresh are automatic. The module has a persisted result outbox and best-effort announcement deduplication. Network failures and crashes may still cause a delayed or, in ambiguous delivery cases, repeated chat result/announcement; do not promise exactly-once external delivery. Twitch chat messages are read through official EventSub WebSocket subscriptions. The bot cannot receive messages sent while it is disconnected. Giveaways are free-entry and do not require subscriptions, follows, purchases or payment. Prize eligibility, legal rules and delivery are the streamer's responsibility. There is no automatic prize delivery and no payment processing.

## Validation

The module has 12 offline tests and a source-level integration smoke test. These verify unique participants, persistence, random selection, reroll exclusion, authorization, OAuth refresh, EventSub subscription construction, failed sends, command preservation, HTTP routing and permissions. The actual Discord/Twitch services, Railway deployment and Windows OBS script have not been live-tested with the user's accounts. Run `node test-stream-integration.js` and `node --check index.js` before deployment. The original v11 code has 96 commands; the integrated version registers 98. Node's built-in SQLite may emit an experimental warning on Node 22.

## Rollback

Keep the original main branch and Railway volume. If the update fails, redeploy the previous known-good commit or restore the original index.js/package.json and remove the stream-integration hooks. Do not delete /data. The new database is named `unfug-stream.sqlite` and is separate from the community database. The OBS connection script backs up the selected scene collection before modification; restore that JSON while OBS is closed if necessary.
